\exercise[1.5] Select all (and only those) statements correctly defining classification, regression, representation learning, and clustering.
\begin{enumerate}
    \item A model trained only to reconstruct its input is necessarily a reinforcement learning agent.
    \item A machine-health estimator may combine a discrete status label and a continuous risk score.
    \item Regression predicts continuous quantities such as price or temperature.
    \item Clustering requires the desired class label for every training example.
    \item A task is unsupervised only because its input is high-dimensional.
    \item Classification predicts one or more discrete labels.
    \item Predicting a binary sentiment label from examples is supervised learning.
    \item Learning an embedding can be useful even if no semantic class label is available.
\end{enumerate}
\solution Before looking at the answers, reduce everything to \textbf{4 definitions}:
\begin{itemize}
    \item \definition{Classification}
        \begin{center}
            \emph{Are we predicting a \textbf{discrete label/category}?}
        \end{center}
        We have an input $x$, and we want to predict a \textbf{discrete label}:
        \begin{equation*}
            f(x) = \hat{y}, \quad \hat{y} \in \left\{C_{1}, C_{2}, \ldots, C_{K}\right\}
        \end{equation*}
        For example, given an image, we want to predict whether it contains a cat, a dog, or a bird. The word \textbf{discrete} means that the output is a finite set of possible values, rather than a continuous range.

        \highspace
        Also, classification can be binary (two classes, e.g., spam vs. not spam) or multi-class (more than two classes, e.g., cat, dog, bird). In some cases, we may also have \textbf{multi-label classification}, where \hl{each input can belong to multiple classes simultaneously.}

    \item \definition{Regression}
        \begin{center}
            \emph{Are we predicting a \textbf{continuous numerical value}?}
        \end{center}
        Again, we have an input $x$, but now the target is a \textbf{continuous quantity}:
        \begin{equation*}
            f(x) = \hat{y}, \quad \hat{y} \in \mathbb{R}
        \end{equation*}
        For example, given the features of a house (size, number of bedrooms, location), we want to predict its price. The crucial \textbf{distinction} from classification is therefore \textbf{what the prediction represents}: a discrete category vs. a continuous value.

    \item \definition{Clustering}
        \begin{center}
            \emph{Are we finding \textbf{groups in unlabeled data}?}
        \end{center}
        This is different from classification and regression. We are \textbf{not given the correct group for every example}. Instead, we have data:
        \begin{equation*}
            D = \left\{x_1, x_2, \ldots, x_N\right\}
        \end{equation*}
        And we want to \textbf{discover some grouping} based on regularities or similarities in those data. Conceptually:
        \begin{equation*}
            \left\{x_1, x_2, \ldots, x_N\right\} \to \left\{\text{cluster}_{1}, \text{cluster}_{2}, \ldots, \text{cluster}_{K}\right\}
        \end{equation*}
        For example, suppose we have customer information but nobody tells us what kinds of customers exist. A clustering algorithm could discover groups corresponding to customers with similar behavior.

    \item \definition{Representation Learning}
        \begin{center}
            \emph{Are we learning \textbf{features/embeddings/representations} from the data?}
        \end{center}
        The primary goal here isn't necessarily to predict a category or numerical value. Instead, we want the model to \textbf{learn a useful representation of the input}. Think:
        \begin{equation*}
            x \to z
        \end{equation*}
        Where $x$ is the original input and $z$ is its learned representation. We have seen this on \autopageref{sec:unsupervised-learning-word-embedding} with word embeddings, where the model learns a vector representation of words that captures semantic meaning, or more generally in autoencoders (\autopageref{fig:autoencoder}), where the model learns a compressed representation of the input data.
\end{itemize}
These definitions tell us \textbf{what task we are trying to solve}.

\begin{table}[!htp]
    \centering
    \begin{tabular}{@{} l p{18em} @{}}
        \toprule
        \textbf{Task} & \textbf{Definition} \\
        \midrule
        \textbf{Classification} & Discrete label(s) \\
        \textbf{Regression} & Continuous value(s) \\
        \textbf{Clustering} & Discover groups, no predefined labels \\
        \textbf{Representation Learning} & Learn useful features / embeddings / representations \\
        \bottomrule
    \end{tabular}
    \caption{Summary of the four tasks: classification, regression, clustering, and representation learning.}
\end{table}

\noindent
In addition, we must also consider \textbf{learning paradigms} (\autopageref{sec:machine-learning-paradigms}), which tell us \textbf{how the learning signal/information is provided to the model during learning}. In other words, the learning paradigm tells us ``\emph{where does the learning signal come from?}''. The three main paradigms are:
\begin{itemize}
    \item \definition{Supervised Learning}: train using inputs \textbf{and desired outputs (labels)}:
        \begin{equation*}
            D = \left\{(x_1, t_1), (x_2, t_2), \ldots, (x_N, t_N)\right\}
        \end{equation*}
        The target $t_i$ tells the model what it should have predicted for input $x_i$. The model learns to map inputs to outputs.

    \item \definition{Unsupervised Learning}: train using the data \textbf{without desired outputs (no labels)}:
        \begin{equation*}
            D = \left\{x_1, x_2, \ldots, x_N\right\}
        \end{equation*}
        The model exploits regularities/structure in the data to learn useful representations or groupings. There is no explicit feedback on what the correct output should be.

    \item \definition{Reinforcement Learning}: learning happens through \textbf{interaction with an environment}:
        \begin{equation*}
            \text{state} \to \text{action} \to \text{reward/penalty}
        \end{equation*}
        The reward provides the learning signal, with the goal of maximizing long-term cumulative reward.
\end{itemize}
Now, we can analyze each statement in the exercise:
\begin{itemize}
    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{A model trained only to reconstruct its input is necessarily a reinforcement learning agent.}}}

        This is \textbf{false}. Reconstructing the input means something like:
        \begin{equation*}
            x \to \text{encoder} \to z \to \text{decoder} \to \hat{x}
        \end{equation*}
        With the goal of minimizing the difference between $x$ and $\hat{x}$:
        \begin{equation*}
            \hat{x} \approx x
        \end{equation*}
        That's the typical setup of an \textbf{autoencoder}.

        Instead, reinforcement learning involves an agent interacting with an environment and receiving rewards or penalties based on its actions. Reconstructing the input does not involve any interaction with an environment or reward signal. Thus, this statement is incorrect.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{A machine-health estimator may combine a discrete status label and a continuous risk score.}}}

        This one is probably among the options that made us hesitate. First of all, a \definition{Machine-Health Estimator} is simply a model that looks at data from a physical machine and estimates \textbf{how healthy the machine is}. For example, imagine an industrial motor equipped with sensors measuring:
        \begin{equation*}
            x = \left[
                \text{temperature}, \text{vibration}, \text{pressure}, \text{RPM}, \ldots
            \right]
        \end{equation*}
        A Neural Network receives those measurements and could produce \textbf{two outputs}:
        \begin{equation*}
            x \to
            \begin{cases}
                \text{status} = \text{``warning''} \\
                \text{risk score} = 0.73
            \end{cases}
        \end{equation*}
        These two outputs correspond to two different tasks:
        \begin{itemize}
            \item The \textbf{status} is a \textbf{discrete label}:
                \begin{equation*}
                    \text{status} \in \left\{\text{``healthy''}, \text{``warning''}, \text{``failure''}\right\}
                \end{equation*}
                This is a \textbf{classification task}, where the model predicts one of several discrete categories.

            \item The \textbf{risk score} is a \textbf{continuous value}:
                \begin{equation*}
                    \text{risk score} \in [0, 1]
                \end{equation*}
                This is a \textbf{regression task}, where the model predicts a continuous quantity.
        \end{itemize}
        A Neural Network can simultaneously perform both tasks, making it a multi-task learning model. Therefore, this statement is \textbf{true}.

        \textcolor{Green3}{\faIcon[regular]{lightbulb} \textbf{Tip:}} we shouldn't assume that a model can \emph{only perform one type} of task.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{Regression predicts continuous quantities such as price or temperature.}}}

        This is simply the definition of regression, so this statement is \textbf{true}.

    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{Clustering requires the desired class label for every training example.}}}

        This is the \textbf{opposite} of the definition of clustering, so this statement is \textbf{false}. If we have:
        \begin{equation*}
            D = \left\{(x_1, t_1), (x_2, t_2), \ldots, (x_N, t_N)\right\}
        \end{equation*}
        And $y_i$ tells us the correct class, then we are in a \textbf{supervised learning} scenario, not clustering. In clustering we instead have:
        \begin{equation*}
            D = \left\{x_1, x_2, \ldots, x_N\right\}
        \end{equation*}
        And try to discover groups such as:
        \begin{equation*}
            \left\{x_1, x_2, \ldots, x_N\right\} \to \left\{\text{cluster}_{1}, \text{cluster}_{2}, \ldots, \text{cluster}_{K}\right\}
        \end{equation*}
        No predefined class labels are required, so this statement is \textbf{false}.

    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{A task is unsupervised only because its input is high-dimen\break{}sional.}}}

        Classic distraction. \hl{Dimensionality has nothing to do with whether learning is supervised or unsupervised.} If we have a $1'000'000$-dimensional image and its label (e.g., ``cat'' or ``dog''), we are in a supervised learning scenario. What matters is \textbf{supervision/targets}, not dimensionality. Therefore, this statement is \textbf{false}.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{Classification predicts one or more discrete labels.}}}

        This is \textbf{true} because it is the definition of classification. If the classification predicts one label, it is called \textbf{single-label classification}. If it predicts multiple labels, it is called \textbf{multi-label classification}. In both cases, the output consists of discrete categories.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{Predicting a binary sentiment label from examples is supervised learning.}}}

        A \definition{Binary Sentiment Label} is a label describing the \textbf{sentiment of something using two possible categories}. For example, suppose we want a model to understand whether a movie review is positive or negative:
        \begin{itemize}
            \item ``\emph{This movie was fantastic!}'' $\to$ \textbf{positive}
            \item ``\emph{I didn't like this movie at all.}'' $\to$ \textbf{negative}
        \end{itemize}
        For example, suppose we want a model to understand whether a movie review is positive or negative:
        \begin{equation*}
            y \in \left\{\text{positive}, \text{negative}\right\}
        \end{equation*}
        So \textbf{binary sentiment classification} is a \textbf{classification task}: given some text, classify its sentiment into one of two categories, typically \textbf{positive} or \textbf{negative}. Since we have \textbf{labeled examples} (the text and its corresponding sentiment label), this is a \textbf{supervised learning} scenario. Therefore, this statement is \textbf{true}.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{Learning an embedding can be useful even if no semantic class label is available.}}}

        \definition{Semantic Class Label} means a label that gives an example an \textbf{explicit human-interpretable category/meaning}. For example, in a dataset of images, a semantic class label could be ``cat'', ``dog'', or ``car''. So the statement means that we might have data $x_1$, $x_2$, $\dots$, $x_{N}$, but nobody has annotated them with meaningful categories such as ``dog'', ``cat'', or ``car''. However, we can still learn an \textbf{embedding} $x \to z$, where $z$ is a useful vector representation of the input $x$. This is often done in \textbf{unsupervised learning} scenarios, where we want to learn a representation that captures important features of the data without relying on explicit labels. Therefore, this statement is \textbf{true}.
\end{itemize}

\exercise[1.5] For each task, select the most appropriate learning paradigm: supervised learning, unsupervised learning, or reinforcement learning.
\begin{itemize}
    \item A model receives paired sensor vectors and binary alarm labels and must learn to predict the alarm label for new vectors.
    \item An agent improves a navigation policy by trial and error in a simulator.
    \item A model receives previous daily temperatures and learns to predict the next day's temperature from labelled examples.
    \item A controller learns by choosing actions and receiving delayed rewards from an environment.
    \item A system receives raw customer records and must discover groups with similar behaviour, without pre-defined labels.
    \item A network maps documents to compact vectors by reconstructing their original bag-of-words representation.
\end{itemize}
\solution The question give 6 scenarios, and for each one we must choose \textbf{Supervised} (S), \textbf{Unsupervised} (U), or \textbf{Reinforcement Learning} (RL). We provided the definitions of these paradigms in the previous exercise, so we can use them to analyze each scenario.
\begin{itemize}
    \item[\textbf{S.}] \textcolor{Green3}{\textbf{\emph{A model receives paired sensor vectors and binary alarm labels and must learn to predict the alarm label for new vectors.}}}

        The keyword here is \textbf{paired sensor vectors and binary alarm labels}. This means that for each input (sensor vector), we have a corresponding output (alarm label):
        \begin{equation*}
            (x_i, t_i) = \left(\text{sensor vector}, \text{alarm label}\right)
        \end{equation*}
        For example:
        \begin{equation*}
            \left[32\degree, 0.23, 1200\text{ RPM}\right] \to \text{``NO ALARM''}
        \end{equation*}
        The model is explicitly given the desired output for each training example. Therefore, this is a \important{Supervised Learning} scenario. More specifically, the \textbf{task} is binary classification (predicting whether an alarm should be triggered or not), but the \textbf{learning paradigm} is supervised learning.

    \item[\textbf{RL.}] \textcolor{Green3}{\textbf{\emph{An agent improves a navigation policy by trial and error in a simulator.}}}

        Here, \emph{agent}, \emph{policy}, and especially \emph{trial and error} are strong indicators for \important{Reinforcement Learning}. Imagine a robot:
        \begin{equation*}
            \text{state} \xrightarrow{\text{choose action}} \text{move left/right/forward} \to \text{new state}
        \end{equation*}
        It tries actions and learns which actions lead to better outcomes.

    \item[\textbf{S.}] \textcolor{Green3}{\textbf{\emph{A model receives previous daily temperatures and learns to predict the next day's temperature from labelled examples.}}}

        This one contains a trap. We might think: ``\emph{it's predicting the future from previous values, so maybe it's unsupervised learning}''. No! The decisive words are ``\emph{from labelled examples}''. For example, the training data could contain:
        \begin{equation*}
            \underbrace{\left[20, 21, 19, 22, 23\right]}_{x} \to \underbrace{24\degree}_{t}
        \end{equation*}
        The correct next-day temperature $t$ is provided during training, so this is a \important{Supervised Learning} scenario. And the \textbf{task} is regression because temperature is continuous.

    \item[\textbf{RL.}] \textcolor{Green3}{\textbf{\emph{A controller learns by choosing actions and receiving delayed rewards from an environment.}}}

        This one should become almost automatic. The keywords are \emph{choosing actions}, \emph{rewards}, and \emph{environment}. That's essentially the definition of \important{Reinforcement Learning}:
        \begin{equation*}
            \text{Agent} \xrightarrow{a_t} \text{Environment} \xrightarrow{r_t} \text{Agent}
        \end{equation*}
        The word \textbf{delayed} is also relevant, because in reinforcement learning, the goal is concerned with maximizing \textbf{long-term cumulative reward}, so an action doesn't necessarily receive its useful reward immediately.

    \item[\textbf{U.}] \textcolor{Green3}{\textbf{\emph{A system receives raw customer records and must discover\break groups with similar behaviour, without pre-defined labels.}}}

        This is exactly the clustering example we discussed in the previous exercise. We have:
        \begin{equation*}
            D = \left\{x_1, x_2, \ldots, x_N\right\}
        \end{equation*}
        But no $\left(x_i, t_i\right)$ pairs. The system discovers groups:
        \begin{equation*}
            D \to C_{1}, C_{2}, \ldots, C_{K}
        \end{equation*}
        The strongest indicator is ``\emph{without pre-defined labels}'', which means\break there are no target outputs provided. Therefore, this is a \important{Unsupervised Learning} scenario. And the \textbf{task} is clustering because the goal is to find groups of similar customers.

    \item[\textbf{U.}] \textcolor{Green3}{\textbf{\emph{A network maps documents to compact vectors by reconstructing their original bag-of-words representation.}}}

        This is probably the least obvious one. The network is essentially doing:
        \begin{equation*}
            x \xrightarrow{\text{encoder}} z \xrightarrow{\text{decoder}} \hat{x}
        \end{equation*}
        Where $x$ is the original document representation, $z$ is the compact representation (embedding), and $\hat{x}$ is the reconstructed document. And training tries to make $\hat{x} \approx x$. This is an \textbf{autoencoder-like reconstruction task}. There are \textbf{no semantic labels} (e.g., ``sports'', ``politics'', etc.) provided for the documents. Instead, the model learns useful structure/representations from the data through reconstruction. Therefore, this is a \important{Unsupervised Learning} scenario. And the \textbf{task} is representation learning because the goal is to learn a compact vector representation of the documents.
\end{itemize}

\exercise[1.5] Which statements correctly describe Hebbian-style perceptron learning as presented in basic neural models? Select all and only those that apply.
\begin{enumerate}
    \item The weights may be updated online, one sample at a time.
    \item The weight update rule is a supervised procedure where target outputs are used.
    \item The method can start from a random initialization.
    \item The weight update rule is identical to the one used to train a deep network with backpropagation.
    \item The update does not depend on the target output.
    \item The update can depend on the input value, target value, and learning rate.
    \item The model does not receive corrections when correctly classifying a sample.
    \item It proves that XOR is linearly separable.
\end{enumerate}
\solution First of all, \emph{what is Hebbian-style perceptron learning?} As introduced on \autopageref{sec:hebbian-learning-rule}, it is a simple learning rule: \hl{the strength of a connection increases according to the simultaneous activation of an input and the \textbf{desired target}.} The idea comes from the biological principle that ``\emph{neurons that fire together, wire together}'' (Hebb Donald, 1949). For the perceptron, this means mathematically (\autopageref{eq:hebbian-weight-change}):
\begin{equation*}
    w_{i}^{(k+1)} = w_i^{(k)} + \Delta w_i = w_i^{(k)} + \eta \cdot x_i \cdot t, \qquad \Delta w_i = \eta \cdot x_i \cdot t
\end{equation*}
Where:
\begin{itemize}
    \item $\eta$ is the \textbf{learning rate}, controlling how much the weights change at each update.
    \item $x_i$ is the \textbf{input value} for the $i$-th input.
    \item $t$ is the \textbf{target output} (desired output) for the current training example.
\end{itemize}
And the algorithm is very simple:
\begin{enumerate}
    \item \textbf{Initialize} the weights $w_i$ randomly (zero or small random values).
    \item \textbf{Set} the learning rate $\eta$ (small positive value).
    \item For each training example $(x, t)$:
        \begin{enumerate}
            \item \textbf{Compute the output} $y$ of the perceptron using the \textbf{current\break weights}.
            \item \textbf{Compare} the output $y$ with the target $t$.
                \begin{itemize}
                    \item If $y \neq t$, \textbf{update the weights} using the Hebbian rule:
                        \begin{equation*}
                            w_{i}^{(k+1)} = w_i^{(k)} + \eta \cdot x_i \cdot t
                        \end{equation*}
                    \item If $y = t$, \textbf{no weight update} is performed.
                \end{itemize}
        \end{enumerate}
    \item \textbf{Repeat} until convergence or for a fixed number of epochs.
\end{enumerate}
Now let's analyze each statement in the exercise:
\begin{itemize}
    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{The weights may be updated online, one sample at a time.}}}

        This is \textbf{true}. The \hl{Hebbian learning rule does not specify that we need to wait for a batch of samples.} In fact, it can be applied in an online manner, where the weights are updated after each individual training example. For example, if we have a training set of $N$ examples, we can iterate through them one by one and update the weights after each example:
        \begin{equation*}
            w_{i}^{(k+1)} = w_i^{(k)} + \eta \cdot x_i^{(n)} \cdot t^{(n)}, \quad n = 1, 2, \ldots, N
        \end{equation*}
        In contrast, batch learning would involve accumulating the weight changes over all examples before applying the update, which is not required by Hebbian learning.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{The weight update rule is a supervised procedure where target outputs are used.}}}

        This is \textbf{true} and it is evident from the weight update formula:
        \begin{equation*}
            \Delta w_i = \eta \cdot x_i \cdot \boxed{t}
        \end{equation*}
        The \textbf{desired target output} $t$ explicitly appears. Therefore the training data contain something like $(x_i, t_i)$ pairs, which is the hallmark of supervised learning.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{The method can start from a random initialization.}}}

        Similar to the first statement, this is \textbf{true}. The Hebbian learning rule does not impose any restrictions on the initial values of the weights. So, we can start with random weights (or even zero weights) and let the learning process adjust them based on the training data.

    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{The weight update rule is identical to the one used to train a deep network with backpropagation.}}}

        The Hebbian learning rule is a simple local update rule based on the input and target output. In contrast, deep neural-network backpropagation involves computing gradients of a loss function with respect to the weights, using the chain rule to propagate errors backward through multiple layers. So they are \textbf{not identical algorithms}.

    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{The update does not depend on the target output.}}}

        This one should be immediate from the equation:
        \begin{equation*}
            \Delta w_i = \eta \cdot x_i \cdot \boxed{t}
        \end{equation*}
        The target output $t$ is explicitly part of the update rule, so this statement is \textbf{false}. Notice also that this answer is the opposite of statement 2, which we already established as true.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{The update can depend on the input value, target value, and learning rate.}}}

        Again, this is \textbf{true} and it is evident from the weight update formula:
        \begin{equation*}
            \Delta w_i = \underbrace{\eta}_{\text{learning rate}} \cdot \underbrace{x_i}_{\text{input}} \cdot \underbrace{t}_{\text{target}}
        \end{equation*}
        This is the easiest statement if we remember the definition of the Hebbian learning rule.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{The model does not receive corrections when correctly classifying a sample.}}}

        According to the Hebbian learning rule algorithm, if the perceptron correctly classifies a sample (i.e., the output $y$ matches the target $t$), then no weight update is performed. This means that the model does not receive any corrections when it is already making correct predictions. Therefore, this statement is \textbf{true}. So:
        \begin{align*}
            \text{correct prediction } y = t &\implies \Delta w = 0 \\
            \text{incorrect prediction } y \neq t &\implies \Delta w = \eta \cdot x_i \cdot t \quad (\text{apply correction})
        \end{align*}

    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{It proves that XOR is linearly separable.}}}

        As discussed on \autopageref{sec:xor-problem}, the XOR problem is a classic example of a function that is \textbf{not linearly separable}. A single-layer perceptron, which uses the Hebbian learning rule, cannot learn to correctly classify the XOR function. Therefore, this statement is \textbf{false}.
\end{itemize}
\begin{takeawaysbox}[: What shoul we actually remember?]
    For a \textbf{misclassified sample}, the Hebbian learning rule updates the weights based on the input, target output, and learning rate:
    \begin{equation*}
        w_{i}^{(k+1)} = w_i^{(k)} + \eta \cdot x_i^{(n)} \cdot t^{(n)}
    \end{equation*}
    And three properties of the Hebbian learning rule are:
    \begin{enumerate}
        \item It is a \textbf{supervised learning} procedure: target $t$ is known and used in the update.
        \item It can be \textbf{applied online}, one sample at a time.
        \item If the sample is correctly classified, no weight update occurs.
    \end{enumerate}
    Finally, the Hebbian learning rule does not solve the XOR problem, which is not linearly separable.
\end{takeawaysbox}

\exercise[1] Consider a perceptron with Sign activation function and $w_0 = -0.5$, $w_1= 1$, $w_2=1$. What outputs are produced for $(0,0)$, $(0,1)$, $(1,0)$, $(1,1)$? (Correct answer full grade, wrong answer 0.25 penalization)
\begin{itemize}
    \item $1, 0, 0, 0$
    \item $0, 0, 0, 1$
    \item $0, 1, 0, 1$
    \item $1, 1, 1, 0$
    \item $0, 1, 1, 1$
\end{itemize}
\solution A perceptron computes a weighted sum (\autopageref{eq:perceptron-activation}):
\begin{equation*}
    a = w_0 + w_1 x_1 + w_2 x_2 + b
\end{equation*}
And then applies the Sign activation function:
\begin{equation*}
    y = \text{Sign}(a) =
    \begin{cases}
        1, & \text{if } a \geq 0 \\
        0, & \text{if } a < 0
    \end{cases}
\end{equation*}
In this case, we have $w_0 = -0.5$, $w_1 = 1$, $w_2 = 1$, and no bias term $b$:
\begin{equation*}
    a = -0.5 + 1 \cdot x_1 + 1 \cdot x_2
\end{equation*}
Then, for each input pair $(x_1, x_2)$, we compute $a$ and then apply the Sign function to get the output $y$:
\begin{itemize}
    \item $(0,0)$:
        \begin{equation*}
            a = -0.5 + 1 \cdot 0 + 1 \cdot 0 = -0.5 \implies y = \text{Sign}(-0.5) = 0
        \end{equation*}
    \item $(0,1)$:
        \begin{equation*}
            a = -0.5 + 1 \cdot 0 + 1 \cdot 1 = 0.5 \implies y = \text{Sign}(0.5) = 1
        \end{equation*}
    \item $(1,0)$:
        \begin{equation*}
            a = -0.5 + 1 \cdot 1 + 1 \cdot 0 = 0.5 \implies y = \text{Sign}(0.5) = 1
        \end{equation*}
    \item $(1,1)$:
        \begin{equation*}
            a = -0.5 + 1 \cdot 1 + 1 \cdot 1 = 1.5 \implies y = \text{Sign}(1.5) = 1
        \end{equation*}
\end{itemize}
So, the outputs for the input pairs $(0,0)$, $(0,1)$, $(1,0)$, $(1,1)$ are:
\begin{equation*}
    0, 1, 1, 1
\end{equation*}

\noindent
\exercise[1.5] Choose the coherent output-layer and loss design choice. For each task, select ``Coherent'' or ``Not Coherent''.
\begin{itemize}
    \item A reconstruction loss when the target is to reproduce an input vector.
    \item Softmax over all labels for multi-label classification where several labels may be true at once.
    \item Single sigmoid output with binary cross-entropy for binary classification.
    \item Softmax output with categorical cross-entropy for mutually exclusive\break multi-class classification.
    \item Independent sigmoid outputs with binary cross-entropy for multi-label classification.
    \item Linear output with squared-error loss for scalar regression.
    \item One scalar regression output with binary cross-entropy for an unrestricted real-valued target.
\end{itemize}
\solution This exercise is basically checking whether the \textbf{output activation and the loss function match the task}. The easiest way to solve this is to ask ourselves: ``\emph{what kind of output must the network represent?}''. Then choose an activation whose output range/structure matches that target, and a loss that makes sense for that output.
\begin{itemize}
    \item \emph{A reconstruction loss when the target is to reproduce an input vector.}\phantomsection\label{def:reconstruction-loss}

        First of all, the terminology ``\emph{\definition{Reconstruction Loss}}'' sounds like a special loss function, but it is \textbf{usually not one specific mathematical loss}. It simply means that the \textbf{loss measures how well the model reconstructs its input}. The goal is something like:
        \begin{equation*}
            x \to \hat{x}
        \end{equation*}
        And we want something like:
        \begin{equation*}
            \hat{x} \approx x
        \end{equation*}
        That is exactly what happens in an autoencoder/reconstruction task. Compare the reconstructed vector with the original input vector using a reconstruction loss (e.g., mean squared error). This is a \important{coherent} design choice.

    \item \emph{Softmax over all labels for multi-label classification where several labels may be true at once.}

        Softmax (\autopageref{def:softmax-activation-function}) takes a \textbf{vector} of real-valued scores (called logits) and \textbf{converts them into a probability distribution}. Mathematically:
        \begin{equation*}
            \sum_{k=1}^{K} p_k = 1, \quad p_k \in [0, 1]
        \end{equation*}
        That creates \textbf{competition between classes}. For example $\left[0.7, 0.2, 0.1\right]$ means the model is distributing one unit of probability among mutually exclusive alternatives. But in \textbf{multi-label classification}, several labels can be true simultaneously. For example, an image may contain a dog, a person, and a grass. Those \textbf{labels should not compete for a total probability of 1}. Therefore, using softmax for multi-label classification is \important{not coherent}.

    \item \emph{Single sigmoid output with binary cross-entropy for binary classification.}

        A neural network doing classification has roughly this structure:
        \begin{equation*}
            \text{input} \to \text{hidden layers} \to \text{output layer}
        \end{equation*}
        Suppose the task is ``\emph{given an email, decide whether it is \textbf{spam or not spam}}''. That's \textbf{binary classification} because there are two possible classes: \emph{spam} or \emph{not spam}. Now the network needs some way to \textbf{express its answer}. That's what the \textbf{output layer} is for.

        Instead of directly outputting the word ``\emph{spam}'', we can have \textbf{one output neuron} producing a number:
        \begin{equation*}
            \text{email} \to \text{Neural Network} \to \underbrace{\hat{y} \in [0, 1]}_{\text{e.g., } 0.87}
        \end{equation*}
        We decide that this number means something like:
        \begin{equation*}
            \hat{y} = 0.87 = \text{high confidence/probability for class 1 (spam)}
        \end{equation*}
        This is the ``\emph{single output}'' part. But an ordinary neuron initially computes an unrestricted number:
        \begin{equation*}
            z = w^{T} x + b \in \mathbb{R}
        \end{equation*}
        Which could be anything, e.g., $5.3$, $-17$, $0.4$, etc. We want the final output between $0$ and $1$, so we put a \textbf{sigmoid activation function} on that output neuron (\autopageref{sec:sigmoid-activation-function}):
        \begin{equation*}
            \hat{y} = \sigma(z) = \frac{1}{1 + e^{-z}} \in (0, 1)
        \end{equation*}
        So ``\emph{single sigmoid output}'' means simply that the network has \textbf{one output neuron}, and that neuron uses \textbf{sigmoid as its activation function}.

        We're now at:
        \begin{equation*}
            \text{email} \to \text{Neural Network} \to z \to \text{sigmoid} \to \hat{y} \in (0, 1)
        \end{equation*}
        There is one final problem: \textbf{how do we train it?} Suppose the training example tells us the email really is spam: $y = 1$. And the network predicts $\hat{y} = 0.87$. We need a loss function that says how bad the prediction $\hat{y}$ is compared with the correct answer $y$.

        For this particular binary setup (i.e., one output neuron with sigmoid activation), a suitable loss function is \definition{Binary Cross-Entropy} (\autopageref{eq:bce-loss}). It is defined as:
        \begin{equation*}
            \mathcal{L}_{\text{BCE}} = - \left[y \cdot \log(\hat{y}) + (1 - y) \cdot \log(1 - \hat{y})\right]
        \end{equation*}
        But let's focus on what it \textbf{does}.

        \begin{center}
            \begin{tabular}{@{} c c c @{}}
                \toprule
                \textbf{Model prediction $\hat{y}$} & \textbf{Interpretation} & \textbf{BCE} \\
                \midrule
                $0.99$ & Very confidently correct & $\approx 0.01$ \\
                $0.9$  & Correct & $\approx 0.11$ \\
                $0.5$  & Unsure & $\approx 0.69$ \\
                $0.1$  & Wrong & $\approx 2.30$ \\
                $0.01$ & Very confidently wrong & $\approx 4.61$ \\
                \bottomrule
            \end{tabular}
        \end{center}

        So BCE has a desirable property: \hl{it penalizes the model more when it is confidently wrong, and less when it is confidently correct.} This is exactly what we want for a binary classification task. Therefore, ``\emph{single sigmoid output with binary cross-entropy for binary classification}'' is a \important{coherent} design choice.

    \item \emph{Softmax output with categorical cross-entropy for mutually exclusive multi-class classification.}

        Suppose we want to classify an image as:
        \begin{equation*}
            \left\{\text{cat}, \text{dog}, \text{horse}\right\}
        \end{equation*}
        Unlike binary classification, we now have \textbf{3 possible classes}. And the question says \textbf{mutually exclusive}, which means that each image can belong to \textbf{exactly one class}. So instead of the single output neuron we used before, it's natural to have \textbf{one output for each class}: (output neuron 1) \emph{cat}, (output neuron 2) \emph{dog}, (output neuron 3) \emph{horse}. Before the final activation, the network might produce arbitrary scores:
        \begin{equation*}
            z = \left[z_{\text{cat}}, z_{\text{dog}}, z_{\text{horse}}\right] \in \mathbb{R}^{3} \xrightarrow{\text{for example}}
            \begin{bmatrix}
                1.2 \\
                3.7 \\
                0.4
            \end{bmatrix}
        \end{equation*}
        These are usually called \textbf{logits}.

        Now, we'd like to transform those arbitrary scores into something we can interpret as a probability distribution over the classes. That's exactly what the \textbf{softmax activation function} does (\autopageref{def:softmax-activation-function}):
        \begin{equation*}
            \text{softmax}(z_i) = \frac{e^{z_i}}{\sum_{j=1}^{K} e^{z_j}}, \quad i = 1, 2, \ldots, K
        \end{equation*}
        Where $K$ is the number of classes. For our example:
        \begin{equation*}
            \text{softmax}\left(
                \begin{bmatrix}
                    1.2 \\
                    3.7 \\
                    0.4
            \end{bmatrix}\right) \approx
            \begin{bmatrix}
                0.08 \\
                0.90 \\
                0.02
            \end{bmatrix}
        \end{equation*}
        So the network is now saying: ``\emph{I think it's a dog with 90\% probability, a cat with 8\% probability, and a horse with 2\% probability}''. And crucially, the probabilities sum to 1, which is \textbf{exactly what we want for mutually exclusive classes}.

        Finally, we need a loss function to train the network. For multi-class classification with mutually exclusive classes, the standard choice is \definition{Categorical Cross-Entropy} (\autopageref{eq:cce-loss}). It is defined as:
        \begin{equation*}
            \mathcal{L}_{\text{CCE}} = - \sum_{i=1}^{K} y_i \cdot \log(\hat{y}_i)
        \end{equation*}
        Because only one entry of $y$ is 1 (the correct class) and everything else disappears, this simplifies to:
        \begin{equation*}
            \mathcal{L}_{\text{CCE}} = - \log(\hat{y}_{\text{correct class}})
        \end{equation*}
        This loss function penalizes the model based on how much probability it assigns to the correct class. If the model assigns a high probability to the correct class, the loss is low; if it assigns a low probability, the loss is high.

        In our example, if the correct class is \emph{dog}, then:
        \begin{equation*}
            \mathcal{L}_{\text{CCE}} = - \log(0.90) \approx 0.105
        \end{equation*}
        Which is a low loss, indicating a good prediction. If the correct class were \emph{cat}, then:
        \begin{equation*}
            \mathcal{L}_{\text{CCE}} = - \log(0.08) \approx 2.525
        \end{equation*}
        Which is a high loss, indicating a poor prediction. Therefore, ``\emph{Softmax output with categorical cross-entropy for mutually exclusive multi-class classification}'' is a \important{coherent} design choice.

    \item \emph{Independent sigmoid outputs with binary cross-entropy for multi-label classification.}

        Suppose we classify the contents of an image using these labels:
        \begin{equation*}
            \left\{\text{dog}, \text{person}, \text{car}\right\}
        \end{equation*}
        In the previous \textbf{mutually exclusive multi-class} problem, exactly one answer could be correct. But here, \textbf{several labels can be correct simultaneously}. For example, an image could contain both a dog and a person:
        \begin{equation*}
            y = \left[1, 1, 0\right] \quad \text{(dog and person are present, car is not)}
        \end{equation*}
        This is \textbf{multi-label classification}.

        The softmax activation function makes sense if the classes compete with each other, because the output probabilities must sum to 1:
        \begin{equation*}
            \sum_{k=1}^{K} p_k = 1
        \end{equation*}
        But that's exactly what we \textbf{don't want} in multi-label classification. An image could very confidently contain both a dog and a person. In fact, if the model predicts:
        \begin{equation*}
            \hat{y} = \left[0.9, 0.8, 0.1\right]
        \end{equation*}
        That means the model is 90\% confident there's a dog, 80\% confident there's a person, and 10\% confident there's a car. It is perfectly fine because these are \textbf{not competing alternatives}. So \hl{no softmax} is needed.

        Instead, we give \textbf{each label its own output neuron} and its own sigmoid activation function. For example:
        \begin{equation*}
            \hat{y}_{\text{dog}} = \sigma(z_{\text{dog}}), \quad \hat{y}_{\text{person}} = \sigma(z_{\text{person}}), \quad \hat{y}_{\text{car}} = \sigma(z_{\text{car}})
        \end{equation*}
        The network might produce:
        \begin{equation*}
            \hat{y} = \left[\hat{y}_{\text{dog}}, \hat{y}_{\text{person}}, \hat{y}_{\text{car}}\right] = \left[0.95, 0.98, 0.03\right]
        \end{equation*}
        And we interpret these as independent probabilities for each label. Each sigmoid only cares about its own logit:
        \begin{equation*}
            \hat{y}_k = \sigma(z_k) = \frac{1}{1 + e^{-z_k}}, \quad k = 1, 2, \ldots, K
        \end{equation*}
        That's what ``\emph{independent sigmoid outputs}'' means.

        Finally, we need a loss function. We just said that Binary Cross-Entropy (BCE) makes sense when we have a binary question (\emph{is this label present or not?}). Well, \textbf{each label in a multi-label problem is a binary classification problem}. So we can apply BCE to \textbf{each output independently}. The architecture is essentially: several binary classifiers, one for each label.

        Thus, ``\emph{Independent sigmoid outputs with binary cross-entropy for multi-label classification}'' is a \important{coherent} design choice.

    \item \emph{Linear output with squared-error loss for scalar regression.}

        \textbf{Regression} means predicting a \textbf{continuous numerical value}, rather than a class. For example, given information about a house (size, rooms, location, age, etc.), we want to predict its price.

        With ``\emph{\textbf{scalar regression}}'', it means we are simply \textbf{predicting one number} $y \in \mathbb{R}$ (e.g., the price of a house), rather than a vector of several numbers.

        The simplest way to do this is to have a \textbf{linear output neuron}. This wording can be confusing, but it does \textbf{not} mean the entire neural network is linear. It simply means that the \hl{final output neuron does not have a non-linear activation function applied to it.} Instead, it outputs a linear combination of its inputs:
        \begin{equation*}
            \hat{y} = w^{T} x + b \in \mathbb{R}
        \end{equation*}
        This is exactly what we want for regression: the output can be any real number. In contrast with, for example, a sigmoid output, which is restricted to the range $(0, 1)$. If we're predicting an unrestricted temperature, sigmoid would be a strange choice because we'd artificially restrict the prediction to $0 < \hat{y} < 1$. So for an \textbf{unrestricted real-valued regression target}, a linear output is a natural choice.

        As always, we need a loss function to train the network. Suppose the true temperature is:
        \begin{equation*}
            y = 20\degree \text{C}
        \end{equation*}
        And the network predicts:
        \begin{equation*}
            \hat{y} = 18\degree \text{C}
        \end{equation*}
        We need a loss function that measures how far is our numerical prediction $\hat{y}$ from the correct numerical value $y$. The basic squared error loss is a natural choice (\autopageref{box:mse}):
        \begin{equation*}
            \mathcal{L} = \left(y - \hat{y}\right)^2
        \end{equation*}
        For our example:
        \begin{equation*}
            \mathcal{L} = \left(20 - 18\right)^2 = 4
        \end{equation*}
        If instead the network predicted $\hat{y} = 10\degree \text{C}$, the loss would be:
        \begin{equation*}
            \mathcal{L} = \left(20 - 10\right)^2 = 100
        \end{equation*}
        So closer numerical predictions result in smaller loss values, and large errors are penalized more strongly because they're squared.

        Across many samples, averaging these squared errors gives the familiar \definition{Mean Squared Error (MSE)} loss:
        \begin{equation*}
            \mathcal{L}_{\text{MSE}} = \frac{1}{N} \sum_{i=1}^{N} \left(y_i - \hat{y}_i\right)^2
        \end{equation*}
        Again, suppose we're predicting temperature:
        \begin{equation*}
            \text{sensor data} \to \text{neural network} \to \hat{y} \in \mathbb{R} \quad (\text{predicted temperature})
        \end{equation*}
        The task is scalar regression (predict one continuous number). We use a linear output neuron (allows unrestricted real-valued predictions) and during training we compare the prediction $\hat{y}$ with the true temperature $y$ using squared-error loss (measures numerical prediction error). Therefore:
        \begin{equation*}
            \text{Scalar regression} \to \text{Linear output} \to \text{Squared-error loss / MSE}
        \end{equation*}
        Is a \important{coherent} design choice.

    \item \emph{One scalar regression output with binary cross-entropy for an unrestricted real-valued target.}

        The first part of the statement ``\emph{one scalar regression output}'' means the network has one output neuron producing one number: $\hat{y} \in \mathbb{R}$. And because this is regression, that number represents a \textbf{continuous quantity}, not a class. And ``\emph{unrestricted real-valued target}'' makes this even more explicit: the true value $y$ can be any real number, not just 0 or 1.

        Here, the problem is the loss function. Binary Cross-Entropy (BCE) wants the prediction to approach the \textbf{binary target}. For example, if the target $y \in \left\{0, 1\right\}$ is $y = 1$, then BCE will penalize the model based on how close $\hat{y}$ is to 1 (i.e., $\hat{y} \to 1$, then $\mathcal{L}_{\text{BCE}} \to 0$). But if the target is unrestricted, say $y = 3.14$, then BCE doesn't make sense because it expects a binary target. The model will be confused: it will try to push $\hat{y}$ toward 0 or 1, but the true value is something else entirely.

        A \textbf{better choice} for an unrestricted real-valued target is to use a\break \textbf{squared-error loss (MSE)} which directly asks: \emph{how far is our prediction $\hat{y}$ from the correct real value $y$?} So, ``\emph{One scalar regression output with binary cross-entropy for an unrestricted real-valued target}'' is \important{not coherent}.
\end{itemize}

\noindent
\exercise[1.5] Which statements about momentum or adaptive learning-rate methods are correct? Select all that apply and only those.
\begin{itemize}
    \item They replace the dataset with hand-written rules.
    \item Momentum can accumulate update directions across iterations.
    \item They may interact with learning-rate selection.
    \item They are optimization choices, not definitions of supervised learning.
    \item They guarantee the global optimum for every neural network.
    \item They can make gradient descent variants more effective in practice.
    \item They remove the need for a training objective.
    \item Adaptive methods can change effective step sizes across layers.
\end{itemize}
\solution Before analyzing the statements individually, let's establish the \textbf{basic idea}.

\highspace
\textcolor{Green3}{\faIcon{question-circle} \textbf{Where are we in the neural-network pipeline?}} During training, we have a loss $E(w)$ and backpropagation computes gradients such as:
\begin{equation*}
    \nabla E(w) = \frac{\partial E}{\partial w}
\end{equation*}
Then \textbf{gradient descent} use those gradients to change the weights:
\begin{equation*}
    w_{k+1} = w_k - \eta \cdot \nabla E(w_k)
\end{equation*}
Where $\eta$ is the \textbf{learning rate}. So conceptually we are in the \textbf{optimization step} of training:
\begin{equation*}
    \text{Forward pass} \to \text{Loss} \to \text{Backpropagation} \to \boxed{\text{Optimizer}} \to \text{Update weights}
\end{equation*}
\textcolor{Green3}{\faIcon{book} \textbf{What is momentum?}} Ordinary gradient descent essentially looks at the \textbf{current} gradient and move accordingly (i.e., the steepest descent direction). But if the loss surface is \textbf{bumpy} (i.e., has many local minima or oscillations), then the current gradient may not be a good indicator of the overall direction to move. Momentum is a technique that \textbf{accumulates past gradients} to smooth out the update direction. In other words, it carries information from \textbf{previous updates}. Mathematically, momentum can be expressed adding a velocity term $v$ called \emph{inertia}:
\begin{equation*}
    v_{t} = \alpha \cdot v_{t-1} - \eta \cdot \nabla E(w_t)
\end{equation*}
Followed by the weight update:
\begin{equation*}
    w_{t+1} = w_t + v_t
\end{equation*}
The crucial term $\alpha \cdot v_{t-1}$ means that the new movement partially depends on the \textbf{previous movement}. Imagine gradient descent repeatedly wants to move in roughly the same direction, let's say rightwards. Momentum builds up movement in that persistent direction. That's the \textbf{intuition} behind momentum: the \hl{optimization develops some \emph{inertia} instead of completely forgetting its previous direction at every iteration.}

\highspace
\textcolor{Green3}{\faIcon{brain} \textbf{Adaptive learning rates.}} Now consider another problem. With ordinary gradient descent, we have one learning rate $\eta$. But \hl{different parameters/layers may behave very differently}, because gradient magnitudes vary across layers, and early layers can receive vanishing gradients (i.e., very small gradients, see vanishing gradient problem on \autopageref{def:vanishing-gradient-problem}). So ideally we \textbf{should use separate adaptive learning rates for each parameter}. Methods such as AdaGrad, RMSProp, and Adam modify the effective step size based on gradient history.

\highspace
So the big-picture distinction is:
\begin{itemize}
    \item \textbf{Momentum}: uses previous update/gradient information to build \emph{inertia}.
    \item \textbf{Adaptive methods}: adapt effective step sizes using gradient history.
\end{itemize}
And Adam (Adaptive Moment Estimation) combines ideas from both momentum and adaptive learning rates.

\highspace
Now let's analyze the statements individually:
\begin{itemize}
    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{They replace the dataset with hand-written rules.}}}

        This is \textbf{false}. The reason it's false is simply that momentum/adaptive methods are \textbf{optimization methods}. They affect parameter updates. They don't replace the training data with manually programmed rules. In other words, \hl{data remain data, and the optimizer changes how parameters are updated.}

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{Momentum can accumulate update directions across iterations.}}}

        This is \textbf{true}. As explained above, momentum accumulates information from previous gradients to smooth out the update direction. The velocity term $v_t$ depends on the previous velocity $v_{t-1}$, which means that the optimizer retains some memory of past updates. This allows it to build up speed in consistent directions and dampen oscillations in noisy gradients.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{They may interact with learning-rate selection.}}}

        This is \textbf{true}. Adaptive methods explicitly affect the \textbf{effective step size}, while momentum itself also contains the learning rate $\eta$ in its update equation. So these optimization choices interact with learning-rate behavior/selection.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{They are optimization choices, not definitions of supervised\break learning.}}}

        This is obviously \textbf{true}. Supervised learning is a paradigm where the learning signal/target comes from labeled data. Whereas momentum and adaptive methods are \textbf{optimization techniques}, so how optimization updates parameters.

        \newpage

    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{They guarantee the global optimum for every neural network.}}}

        This is \textbf{false}. Neural-Network loss landscapes are generally non-convex, and these methods do \textbf{not} provide a universal guarantee that training reaches the global minimum. The word ``\emph{guarantee}'' is especially suspicious in this context. While momentum and adaptive methods \textbf{can help optimization converge faster or escape shallow local minima}, they do not guarantee finding the global optimum.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{They can make gradient descent variants more effective in practice.}}}

        This is \textbf{true}. In practice, momentum and adaptive methods often improve convergence speed and stability of training. Also, notice the cautious wording again: ``\emph{can make ... more effective}'', not ``\emph{always make ... more effective}''. So momentum and adaptive learning-rate methods exist precisely as practical improvements/modifications of basic gradient-based optimization.

    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{They remove the need for a training objective.}}}

        This is \textbf{false}. The objective is the function we're trying to optimize, typically the loss function $\mathcal{L}(w)$. The optimization goal is to minimize that loss:
        \begin{equation*}
            w^{*} = \argmin_{w} \mathcal{L}(w)
        \end{equation*}
        Momentum or Adam changes \textbf{how we search for good} $w$. It doesn't eliminate $\mathcal{L}$. In fact, without an objective, there would be no gradient $\nabla_{w} \mathcal{L}$ for the optimizer to use.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{Adaptive methods can change effective step sizes across layers.}}}

        This is \textbf{true}. Think about ordinary gradient descent:
        \begin{equation*}
            \Delta w = - \eta g
        \end{equation*}

        Where $g = \nabla E(w)$ is the gradient, and $\eta$ is the global learning rate. Adaptive methods modify the \textbf{effective size of the update} based on gradient history. Consequently, parameters belonging to different layers can receive differently scaled updates. So:
        \begin{equation*}
            \text{different gradient histories} \implies \text{different effective step sizes}
        \end{equation*}
        And therefore different layers can indeed end up with different effective step sizes. Again, this statement says ``\emph{can}'', not that the optimizer necessarily assigns exactly one explicit learning rate to each layer.
\end{itemize}

\noindent
\exercise[1] Which statements about backpropagation through time are correct? Select all and only those.
\begin{itemize}
    \item It cannot suffer from vanishing gradients.
    \item Long unfolded sequences can behave like very deep computational graphs.
    \item It is irrelevant to recurrent neural networks.
    \item It can propagate error signals from later outputs to earlier recurrent states.
    \item It requires the hidden state to be manually labelled at every step.
    \item It applies the same chain-rule principle used in ordinary backpropagation.
    \item It unfolds the recurrent computation over time.
    \item It trains weights that are shared across time steps.
\end{itemize}
\solution Before analyzing the statements individually, let's understand the intuition behind backpropagation through time (BPTT).

\highspace
\textcolor{Green3}{\faIcon{question-circle} \textbf{What problem is BPTT trying to solve?}} A \emph{vanilla} Recurrent Neural Network (RNN) has a hidden state $h_t$ that is updated at each time step $t$ based on the previous hidden state $h_{t-1}$ and the current input $x_t$:
\begin{equation*}
    h_t = f\left(
        W_{x}x_t + W_{h}h_{t-1} + b
    \right)
\end{equation*}
Which means that the hidden state at time $t$ depends on all previous inputs and hidden states. That's what gives an RNN its \textbf{temporal memory}.\footnote{
    Recurrent Neural Networks (RNNs) were developed because ordinary Feed-Forward Networks cannot handle sequential data. For instance, to predict the next word in a sentence, we must consider the preceding words. A Feed-Forward Network has no recurrent state/memory connecting successive inputs, so it cannot remember previous words. RNNs solve this by maintaining a hidden state that is updated at each time step, allowing the network to retain information from earlier inputs.
} But now suppose at time $t = 4$ the network makes a bad prediction and produces a loss $E_{4}$. That prediction didn't depend only on $x_4$. Through the recurrent states, it may depend on: $x_4$, $x_3$, $x_2$, and $x_1$. So the error at $t = 4$ potentially needs to influence computations that happened at earlier time steps.

\highspace
\textcolor{Green3}{\faIcon{check} \textbf{First we unroll the RNN.}} The actual RNN conceptually has a recurrent loop (i.e., $h_t$ depends on $h_{t-1}$). For training, we represent that recurrence across a finite sequence as:
\begin{equation*}
    h_0 \to h_1 \to h_2 \to h_3 \to h_4
\end{equation*}
With the corresponding inputs:
\begin{equation*}
    \underbrace{h_0}_{x_0} \to \underbrace{h_1}_{x_1} \to \underbrace{h_2}_{x_2} \to \underbrace{h_3}_{x_3} \to \underbrace{h_4}_{x_4}
\end{equation*}
This is called \textbf{unrolling}/\textbf{unfolding the RNN through time}. Unrolling creates copies of the RNN cell for the different time steps, turning the recurrent computation into a DAG on which ordinary backpropagation can operate. But there's an extremely important detail: \hl{these aren't independent Neural-Network layers with independent weights.} The RNN uses the \textbf{same parameters at every time step}. For example:
\begin{align*}
    h_1 &= f\left(
        W_{x}x_1 + W_{h}h_{0} + b
    \right) \\
    h_2 &= f\left(
        W_{x}x_2 + W_{h}h_{1} + b
    \right) \\
    h_3 &= f\left(
        W_{x}x_3 + W_{h}h_{2} + b
    \right) \\
    h_4 &= f\left(
        W_{x}x_4 + W_{h}h_{3} + b
    \right)
\end{align*}
Notice that the same $W_x$, $W_h$, and $b$ are used at every time step. That's \textbf{weight sharing through time}.

\highspace
\textcolor{Green3}{\faIcon{tools} \textbf{Then we do ordinary backpropagation on this unrolled graph.}} Here there is the central idea of Backpropagation Through Time (BPTT): \hl{ordinary backpropagation applied to the RNN unrolled through time.} Suppose an error occurs at a later time:
\begin{equation*}
    h_1 \to h_2 \to h_3 \to h_4 \to E_4
\end{equation*}
During backpropagation, information flows backward:
\begin{equation*}
    E_4 \to h_4 \to h_3 \to h_2 \to h_1
\end{equation*}
Therefore an error occurring \textbf{later in the sequence} can affect gradients associated with \textbf{earlier recurrent states}. Mathematically, this is just the \textbf{chain rule}, exactly like ordinary backpropagation:
\begin{equation*}
    \frac{\partial E_t}{\partial h_k} = \frac{\partial E_t}{\partial h_t} \cdot \frac{\partial h_t}{\partial h_{t-1}} \cdot \frac{\partial h_{t-1}}{\partial h_{t-2}} \cdots \frac{\partial h_{k+1}}{\partial h_k}
\end{equation*}
\textcolor{Red2}{\faIcon{exclamation-triangle} \textbf{Why do long sequences cause problems?}} Suppose we unroll an RNN for a long sequence of length $T$, say $T = 100$ time steps. Computationally, we've created something that behaves somewhat like a network that's \textbf{100 layer deep in time}:
\begin{equation*}
    h_1 \to h_2 \to h_3 \to \cdots \to h_{100}
\end{equation*}
And during Backpropagation Through Time (BPTT) we're repeatedly multiplying gradients through the chain rule:
\begin{equation*}
    \frac{\partial E_t}{\partial h_k} = \frac{\partial E_t}{\partial h_t} \cdot \prod_{i=k+1}^{t} \frac{\partial h_i}{\partial h_{i-1}}
\end{equation*}
If those factors repeatedly have magnitude below 1:
\begin{equation*}
    0.5 \cdot 0.5 \cdot 0.5 \cdots \approx 0
\end{equation*}
The \textbf{gradient vanishes}. And similarly, if those factors repeatedly have magnitude above 1:
\begin{equation*}
    2 \cdot 2 \cdot 2 \cdots \approx \infty
\end{equation*}
The \textbf{gradient explodes}. That's why vanilla RNNs trained with BPTT have the famous \textbf{vanishing/exploding gradient problem}, especially over long sequences.
\begin{gather*}
    \text{RNN has recurrence over time} \\
    \downarrow \\
    \text{Unroll it across the sequence} \\
    \downarrow \\
    \text{Same weights are reused at every time step} \\
    \downarrow \\
    \text{Apply ordinary chain-rule backpropagation} \\
    \downarrow \\
    \text{Errors can flow from later to earlier states} \\
    \downarrow \\
    \text{Long chains can cause vanishing/exploding gradients}
\end{gather*}
Now let's analyze the statements individually:
\begin{itemize}
    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{It cannot suffer from vanishing gradients.}}}

        This is \textbf{false}. Actually, BPTT \textbf{can very much suffer from vanishing gradients}. When we unfold an RNN:
        \begin{equation*}
            h_1 \to h_2 \to h_3 \to \cdots \to h_{T}
        \end{equation*}
        And propagate the gradient backward, the chain rule repeatedly multiplies derivatives:
        \begin{equation*}
            \frac{\partial E_t}{\partial h_k} = \frac{\partial E_t}{\partial h_t} \cdot \frac{\partial h_t}{\partial h_{t-1}} \cdot \frac{\partial h_{t-1}}{\partial h_{t-2}} \cdots \frac{\partial h_{k+1}}{\partial h_k}
        \end{equation*}
        For a long sequence, if these factors tend to have magnitude below 1, repeated multiplication makes the gradient approach zero.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{Long unfolded sequences can behave like very deep computational graphs.}}}

        This is \textbf{true}. Suppose the RNN processes 100 time steps. When unfolded:
        \begin{equation*}
            h_1 \to h_2 \to h_3 \to \cdots \to h_{100}
        \end{equation*}
        We now have a computational chain with 100 recurrent applications. It's not 100 independent layers with different weights, the parameters are shared, but from the perspective of \textbf{gradient propagation}, the computational graph is extremely deep.

    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{It is irrelevant to recurrent neural networks.}}}

        This is \textbf{false}. BPTT is specifically the standard backpropagation formulation for recurrent networks. We start with an RNN:
        \begin{equation*}
            h_t = f\left(
                W_{x}x_t + W_{h}h_{t-1} + b
            \right)
        \end{equation*}
        Unfold it:
        \begin{equation*}
            h_1 \to h_2 \to h_3 \to \cdots \to h_{T}
        \end{equation*}
        And then apply backpropagation through this temporal computational graph.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{It can propagate error signals from later outputs to earlier recurrent states.}}}

        This is \textbf{true}. It is one of the fundamental reasons BPTT exists. Imagine:
        \begin{equation*}
            h_1 \to h_2 \to h_3 \to h_4 \to y_4
        \end{equation*}
        And the prediction $y_4$ generates a loss $E_4$. During backpropagation, gradients travel backward through the dependencies:
        \begin{equation*}
            E_4 \to h_4 \to h_3 \to h_2 \to h_1
        \end{equation*}
        So an error at a \textbf{later time} can generate gradients associated with computations at \textbf{earlier time steps}. That's exactly what ``\emph{backpropagation through time}'' means.

    \item[\textcolor{Red2}{\faIcon{times}}] \textcolor{Red2}{\textbf{\emph{It requires the hidden state to be manually labelled at every step.}}}

        This is \textbf{false}. The hidden state $h_t$ is an \textbf{internal representation computed by the RNN}. They arise from the computation itself, not from any external labels. Depending on the task, we may have targets associated with outputs, but that is completely different from manually labelling every hidden state.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{It applies the same chain-rule principle used in ordinary backpropagation.}}}

        This is \textbf{true}. BPTT is \textbf{not a fundamentally different mathematical algorithm} from ordinary backpropagation.
        \begin{enumerate}
            \item Unfold the recurrent computation through time.
            \item Obtain a computational graph that is a DAG (Directed Acyclic\break Graph).
            \item Apply the \textbf{chain rule backward through that graph}.
        \end{enumerate}

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{It unfolds the recurrent computation over time.}}}

        This is \textbf{true}. The recurrent representation looks conceptually like a loop: $h_t \circlearrowleft$. Because the next computation depends on the previous hidden state. For BPTT, we represent those successive applications explicitly:
        \begin{equation*}
            h_1 \to h_2 \to h_3 \to h_4
        \end{equation*}
        This is called \textbf{unfolding} or \textbf{unrolling} the RNN \textbf{through time}.

    \item[\textcolor{Green3}{\faIcon{check}}] \textcolor{Green3}{\textbf{\emph{It trains weights that are shared across time steps.}}}

        This is \textbf{true}. When we draw:
        \begin{equation*}
            h_1 \to h_2 \to h_3 \to h_4
        \end{equation*}
        It might look as though we have four different neural-network layers. But we don't have:
        \begin{equation*}
            W_h^{(1)}, W_h^{(2)}, W_h^{(3)}, W_h^{(4)}
        \end{equation*}
        Instead, the \textbf{same recurrent parameters} are reused at every time step:
        \begin{align*}
            h_1 &= f\left(
                W_{x}x_1 + W_{h}h_{0} + b
            \right) \\
            h_2 &= f\left(
                W_{x}x_2 + W_{h}h_{1} + b
            \right) \\
            h_3 &= f\left(
                W_{x}x_3 + W_{h}h_{2} + b
            \right) \\
            h_4 &= f\left(
                W_{x}x_4 + W_{h}h_{3} + b
            \right)
        \end{align*}
        So the same weights $W_x$, $W_h$, and $b$ are shared across time steps. BPTT therefore computes gradient contributions coming from the different time steps for these \textbf{shared parameters}.
\end{itemize}

\noindent
\exercise[1] For each of the following statements about neural autoencoders, state if they are true or false.
\begin{itemize}[label=\textbf{T/F.}, leftmargin=2cm]
    \item The encoder maps from hidden representation to reconstruction.
    \item Given a sample, its autoencoder's hidden representation can be used as features for another model.
    \item A reconstruction error can be used as a signal for anomaly detection.
    \item A denoising autoencoder receives a corrupted input and learns to recover a clean version.
    \item A sparsity penalty encourages all hidden units to be strongly active for every input.
\end{itemize}
\solution Let's do a quick theory recap before analyzing the statements individually.

\highspace
\textcolor{Green3}{\faIcon{question-circle} \textbf{What is an Autoencoder?}} We encountered this concept briefly earlier when discussing \emph{reconstruction loss} (\autopageref{def:reconstruction-loss}). A neural autoencoder is trained to approximately \textbf{reproduce its input at its output}:
\begin{equation*}
    x \to \text{Autoencoder} \to \hat{x}
\end{equation*}
With the goal:
\begin{equation*}
    \hat{x} \approx x
\end{equation*}
But if all we're doing is copying $x$ to $\hat{x}$, why use a neural network at all? The interesting part is what happens \textbf{inside} (\autopageref{fig:autoencoder}):
\begin{equation*}
    x \xrightarrow{\text{Encoder}} h \xrightarrow{\text{Decoder}} \hat{x}
\end{equation*}
Where $x$ is the original input, $h$ is the \textbf{hidden/latent representation} (or \emph{latent code}), and $\hat{x}$ is the reconstructed input. For example, imagine $x$ is a large vector $x \in \mathbb{R}^{1000}$. The encoder might compress it into a smaller hidden representation $h \in \mathbb{R}^{50}$. Then the decoder tries to reconstruct the original $1000$ values:
\begin{equation*}
    \mathbb{R}^{1000} \xrightarrow{\text{encoder}} \mathbb{R}^{50} \xrightarrow{\text{decoder}} \mathbb{R}^{1000}
\end{equation*}
And because the network must reconstruct $x$ from this constrained representation, $h$ should capture useful structure in the input.

\highspace
\textcolor{Green3}{\faIcon{question-circle} \textbf{How is an Autoencoder trained?}} We compare the input $x$ with the reconstruction $\hat{x}$ using the \textbf{reconstruction loss} we discussed earlier (\autopageref{def:reconstruction-loss}):
\begin{equation*}
    \mathcal{L}_{\text{rec}}\left(x, \hat{x}\right)
\end{equation*}
For example, depending on the data, it might be squared error:
\begin{equation*}
    \mathcal{L}_{\text{rec}}\left(x, \hat{x}\right) = \left\|x - \hat{x}\right\|^2
\end{equation*}
Training tries to make $\hat{x}$ as close to $x$ as possible: $\hat{x} \approx x$. Notice that we \textbf{don't need any semantic class labels} for this. The input itself supplies what must be reconstructed, and that's why we present autoencoders in the chapter on \textbf{unsupervised representation learning}.

\highspace
\textcolor{Green3}{\faIcon{question-circle} \textbf{Why is $h$ useful?}} We aren't necessarily interested in the reconstructed output itself. We hope that the hidden representation $h$:
\begin{equation*}
    h = \text{Encoder}(x)
\end{equation*}
Becomes a useful representation of the input $x$. For example:
\begin{equation*}
    x \in \mathbb{R}^{1000} \to h \in \mathbb{R}^{50}
\end{equation*}
This means that the $50$-dimensional representation $h$ captures the most important information from the original $1000$-dimensional input $x$. Those $50$ numbers can potentially capture important patterns in the original $1000$-dimensional sample. Then we could take $h$ and give it to another machine-learning model as features. This is \textbf{feature extraction} or \textbf{representation learning}.

\highspace
\textcolor{Green3}{\faIcon{tools} \textbf{Three variants of Autoencoders.}} There are many variants of autoencoders, but three common ones are (\autopageref{sec:applications-of-autoencoders}):
\begin{itemize}
    \item \definition{Denoising Autoencoder (DAE)}. Instead of giving the network clean $x$ and asking for $x$, deliberately corrupt the input with noise:
        \begin{equation*}
            x \to \text{add noise} \to \tilde{x}
        \end{equation*}
        Then train the network to reconstruct the original clean input $x$ from the noisy version $\tilde{x}$:
        \begin{equation*}
            \tilde{x} \xrightarrow{\text{Autoencoder}} \hat{x} \approx x
        \end{equation*}
        This helps the network learn to ignore noise and focus on the underlying structure of the data.

    \item \definition{Anomaly Detection Autoencoder (ADA)}. Suppose we train an autoencoder only on \textbf{normal machine behavior}. It becomes good at reconstructing normal samples:
        \begin{equation*}
            x_{\text{normal}} \to \hat{x}_{\text{normal}}
        \end{equation*}
        With:
        \begin{equation*}
            \left\|x_{\text{normal}} - \hat{x}_{\text{normal}}\right\|^2 \approx 0
        \end{equation*}
        Now give it something very unusual that differs substantially from its training distribution. It may reconstruct it poorly:
        \begin{equation*}
            x_{\text{anomaly}} \to \hat{x}_{\text{anomaly}}
        \end{equation*}
        With:
        \begin{equation*}
            \left\|x_{\text{anomaly}} - \hat{x}_{\text{anomaly}}\right\|^2 \gg 0
        \end{equation*}
        Therefore the \textbf{reconstruction error itself can become an anomaly signal}.

    \item \definition{Sparse Autoencoder (SAE)}. We add a constraint encouraging only a \textbf{small subset of hidden units to be active} for a particular input. Conceptually, instead of:
        \begin{equation*}
            h = \left[
                0.8, 0.7, 0.9, 0.6, 0.8, 0.9, \dots
            \right]
        \end{equation*}
        We might encourage something more like:
        \begin{equation*}
            h = \left[
                0, 0, 0.8, 0, 0, 0.6, 0, 0, \dots
            \right]
        \end{equation*}
        This is done by adding a \textbf{sparsity penalty} to the loss function, which encourages most hidden units to be near zero for any given input. This can help the autoencoder learn more distinct features and avoid trivial solutions.
\end{itemize}
Now we can analyze the statements individually:
\begin{itemize}
    \item[\textcolor{Red2}{\textbf{F.}}] \textcolor{Red2}{\textbf{\emph{The encoder maps from hidden representation to reconstruction.}}}

        This is clearly \textbf{false}. An autoencoder has:
        \begin{equation*}
            x \xrightarrow{\text{Encoder}} h \xrightarrow{\text{Decoder}} \hat{x}
        \end{equation*}
        Where $x$ is the input, $h$ is the hidden representation, and $\hat{x}$ is the reconstruction. The encoder maps from the input $x$ to the hidden representation $h$, not from $h$ to $\hat{x}$. The \textbf{decoder} is responsible for mapping from $h$ to $\hat{x}$.

    \item[\textcolor{Green3}{\textbf{T.}}] \textcolor{Green3}{\textbf{\emph{Given a sample, its autoencoder's hidden representation can be used as features for another model.}}}

        This is \textbf{true}. And this is one of the main reasons autoencoders are interesting. The hidden representation $h$ is something the autoencoder has \textbf{learned from the data}. Suppose $x \in \mathbb{R}^{1000}$ and the encoder produces $h \in \mathbb{R}^{50}$. After training, we could discard the decoder and use $h$ as a \textbf{feature vector} for another machine-learning model:
        \begin{equation*}
            x \xrightarrow{\text{trained encoder}} h \xrightarrow{\text{another model}} y
        \end{equation*}

    \item[\textcolor{Green3}{\textbf{T.}}] \textcolor{Green3}{\textbf{\emph{A reconstruction error can be used as a signal for anomaly detection.}}}

        This is \textbf{true}. Imagine training an autoencoder on \textbf{normal examples}. It learns to reconstruct normal patterns well:
        \begin{equation*}
            x_{\text{normal}} \to \hat{x}_{\text{normal}} \approx x_{\text{normal}}
        \end{equation*}
        Therefore:
        \begin{equation*}
            \mathcal{L}_{\text{rec}}\left(x, \hat{x}\right) \text{ is small for normal } x
        \end{equation*}
        Now give it an unusual sample that differs from what it learned. It may reconstruct that sample poorly:
        \begin{equation*}
            \hat{x}_{\text{anomaly}} \not\approx x_{\text{anomaly}}
        \end{equation*}
        Therefore:
        \begin{equation*}
            \mathcal{L}_{\text{rec}}\left(x, \hat{x}\right) \text{ is large for anomalous } x
        \end{equation*}
        So the reconstruction error itself can serve as an anomaly signal.

    \item[\textcolor{Green3}{\textbf{T.}}] \textcolor{Green3}{\textbf{\emph{A denoising autoencoder receives a corrupted input and learns to recover a clean version.}}}

        This is \textbf{true}. It is the definition of a \textbf{denoising autoencoder}. We start with clean data $x$, we deliberately corrupt it $x \to \tilde{x}$, and then give the corrupted version to the network:
        \begin{equation*}
            \tilde{x} \xrightarrow{\text{Encoder}} h \xrightarrow{\text{Decoder}} \hat{x}
        \end{equation*}
        But the desired reconstruction is the \textbf{original clean} $x$, so the loss function compares $\hat{x}$ to $x$:
        \begin{equation*}
            \mathcal{L}_{\text{rec}}\left(x, \hat{x}\right)
        \end{equation*}

    \item[\textcolor{Red2}{\textbf{F.}}]  \textcolor{Red2}{\textbf{\emph{A sparsity penalty encourages all hidden units to be strongly active for every input.}}}

        This is \textbf{false} because it's the \textbf{opposite of sparsity}. If every hidden unit were strongly active:
        \begin{equation*}
            h = \left[
                0.8, 0.7, 0.9, 0.6, 0.8, 0.9, \dots
            \right]
        \end{equation*}
        That's a \textbf{dense activation}. Sparsity instead encourages something like:
        \begin{equation*}
            h = \left[
                0, 0, 0.8, 0, 0, 0.6, 0, 0, \dots
            \right]
        \end{equation*}
        Only a relative small subset of units should be strongly active. So sparsity penalty encourages many hidden activations to be inactive/small, not make every hidden unit strongly active.
\end{itemize}
