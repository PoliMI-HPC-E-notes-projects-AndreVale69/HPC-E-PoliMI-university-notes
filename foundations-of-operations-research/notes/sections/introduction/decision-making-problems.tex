\subsection{Decision-Making Problems}\label{sec:introduction:decision-making-problems}

A \definition{Decision-Making Problem} means \hl{choosing one feasible alternative among many, according to one or more criteria.} It contains three main ingredients: alternatives, feasibility conditions, and criterion.

\highspace
Suppose we have a set of possible decisions $S$. Not every decision may be allowed, so only some belong to the \textbf{feasible set} $X \subseteq S$. Then we judge feasible solutions according to some criterion (e.g., minimize cost, minimize time, maximize profit, etc.). So conceptually:
\begin{center}
    Choose $x \in X$ so that $x$ is as good as possible
\end{center}
The \textbf{difficulty} is often that there are \textbf{too many alternatives}. That is why we need models and algorithms instead of trying possibilities one by one (brute force).

\highspace
\begin{flushleft}
    \textcolor{Red2}{\faIcon{exclamation-triangle} \textbf{Assignment Problem}}
\end{flushleft}
Suppose there are $m$ \textbf{jobs}:
\begin{equation*}
    J_1, \dots, J_m
\end{equation*}
And $m$ \textbf{machines}:
\begin{equation*}
    M_1, \dots, M_m
\end{equation*}
Every job can be executed by every machine. Let $t_{ij}$ be the \textbf{execution time} of job $J_i$ on machine $M_j$. For example:
\begin{center}
    \begin{tabular}{@{} c | c c c @{}}
        \toprule
        & $M_1$ & $M_2$ & $M_3$ \\
        \midrule
        $J_1$ & 2 & 6 & 3 \\
        $J_2$ & 8 & 4 & 9 \\
        $J_3$ & 5 & 7 & 8 \\
        \bottomrule
    \end{tabular}
\end{center}
\noindent
The decision is ``\emph{which job should be assigned to which machine?}''. But there are \textbf{constraints}:
\begin{itemize}
    \item Every job must be assigned to \textbf{exactly one machine};
    \item Every machine must be assigned to \textbf{exactly one job}.
\end{itemize}
And the \textbf{objective} is to \textbf{minimize the total execution time}.

\highspace
\begin{examplebox}[: $m=3$]
    For $m=3$, one possible assignment is:
    \begin{equation*}
        J_1 \to M_1, \quad J_2 \to M_2, \quad J_3 \to M_3
    \end{equation*}
    With total time:
    \begin{equation*}
        t_{11} + t_{22} + t_{33} = 2 + 4 + 8 = 14
    \end{equation*}
    Another possible assignment is:
    \begin{equation*}
        J_1 \to M_3, \quad J_2 \to M_2, \quad J_3 \to M_1
    \end{equation*}
    With total time:
    \begin{equation*}
        t_{13} + t_{22} + t_{31} = 3 + 4 + 5 = 12
    \end{equation*}
    So the second one is better.
\end{examplebox}

\highspace
\textcolor{Red2}{\faIcon{question-circle} \textbf{Why is this an OR problem?}} Because the number of feasible assignments grows very quickly. With $m$ jobs and $m$ machines, there are \hl{$m!$ possible assignments exist.} For example, with only $m=10$ jobs and machines, there are already:
\begin{equation*}
    10! = 3'628'800 \text{ possible assignments}
\end{equation*}
So even a fairly small instance already has millions of possibilities. Therefore, \hl{a compactly described problem can have an enormous solution space.} That theme will appear everywhere in OR.

\highspace
\begin{flushleft}
    \textcolor{Red2}{\faIcon{exclamation-triangle} \textbf{Network design problem}}
\end{flushleft}
We represent the system with a graph
\begin{equation*}
    G=(N,E)
\end{equation*}
Where:
\begin{itemize}
    \item $N$ is the set of nodes;
    \item $E$ is the set of possible links.
\end{itemize}
Each edge:
\begin{equation*}
    \{i,j\}\in E
\end{equation*}
Has a cost $c_{ij}$. The decision is: \emph{\textbf{which links should we build?}} The \textbf{requirements} are:
\begin{itemize}
    \item All nodes must ultimately be connected;
    \item Total cost should be as small as possible.
\end{itemize}
So we want to select a subset $E'\subseteq E$, such that the resulting network remains connected and:
\begin{equation*}
    \sum_{\{i,j\}\in E'} c_{ij}
\end{equation*}
Is minimized. This is the \hl{problem that will later lead to the Minimum Spanning Tree.}

\highspace
\textcolor{Red2}{\faIcon{question-circle} \textbf{But, why is it difficult?}} If there are $m=|E|$ possible edges, each edge can conceptually be: \emph{selected} or \emph{not selected}. Therefore there are \hl{up to $2^m$ possible subsets of edges.} For $m=50$:
\begin{equation*}
    2^{50}\approx 1.13\times 10^{15}
\end{equation*}
Of course, many of these subsets are infeasible because they do not connect all nodes. But brute-force enumeration is still hopeless. So, again, we have a \textbf{huge search space}, and we \textbf{need algorithms to find good solutions}.

\highspace
\begin{flushleft}
    \textcolor{Red2}{\faIcon{exclamation-triangle} \textbf{Shortest path problem}}
\end{flushleft}
We again use a graph, but the \textbf{decision is different}. Suppose the graph represents a road network. \textbf{Nodes} represent \textbf{locations}, and each \textbf{arc} has a \textbf{quantity} such as: distance, travel time, monetary cost. Given an origin $s$ and destination $t$, the problem is to \hl{find the minimum-cost path from $s$ to $t$.}

\highspace
For example, if we have two possible paths:
\begin{enumerate}
    \item $s\to a\to t$
    \item $s\to b\to c\to t$
\end{enumerate}
We compute their costs by summing the arc costs. If:
\begin{equation*}
    c(s,a)+c(a,t)=12
\end{equation*}
While:
\begin{equation*}
    c(s,b)+c(b,c)+c(c,t)=8
\end{equation*}
The second path is preferable.

\highspace
The important point is that the \hl{criterion need not literally be distance.} A ``\emph{shortest}'' path can mean: distance, travel time, or monetary cost. So mathematically, ``\emph{shortest}'' really means ``\textbf{minimum total arc weight}'' according to whatever quantity the weights represent.

\highspace
Already notice that all three problems fit the same OR pattern:
\begin{itemize}
    \item \important{Assignment}
        \begin{itemize}
            \item \textbf{Decision}: job-machine pairs
            \item \textbf{Feasibility}: one job per machine and vice versa
            \item \textbf{Objective}: minimize total execution time
        \end{itemize}
    \item \important{Network design}
        \begin{itemize}
            \item \textbf{Decision}: which edges to select
            \item \textbf{Feasibility}: all nodes connected
            \item \textbf{Objective}: minimize total edge cost
        \end{itemize}
    \item \important{Shortest path}
        \begin{itemize}
            \item \textbf{Decision}: which path to follow
            \item \textbf{Feasibility}: valid path from source to destination
            \item \textbf{Objective}: minimize path cost
        \end{itemize}
\end{itemize}
That abstraction is extremely important. At first the applications look unrelated, but OR looks underneath the story and asks: ``\emph{what are the decisions? What makes them feasible? What do we optimize?}''.

\highspace
\begin{examplebox}[: Personnel scheduling]
    Suppose a hospital must prepare a weekly work schedule. The decision concerns things such as:
    \begin{itemize}
        \item Who works;
        \item On which day;
        \item During which shift.
    \end{itemize}
    The hospital has staffing requirements. For example, ``\emph{at least 5 nurses on Monday morning}''. It may also have constraints such as:
    \begin{itemize}
        \item Maximum weekly hours;
        \item Rest periods;
        \item Employee availability.
    \end{itemize}
    The objective might be to minimize the number of employees required, while still satisfying all staffing requirements.

    \highspace
    Again:
    \begin{itemize}
        \item \textbf{Decision}: schedule of employees;
        \item \textbf{Constraints}: coverage and employment rules;
        \item \textbf{Objective}: use as few resources as possible.
    \end{itemize}
    This kind of problem becomes a classic scheduling/integer optimization problem.
\end{examplebox}

\highspace
\begin{examplebox}[: Service management]
    Imagine a bank, airport, supermarket, or public office. At each moment, management must decide ``\emph{how many service counters should be open?}''.

    \highspace
    Opening more counters improves service but costs more. Opening too few counters reduces staffing cost but increases waiting time. We might impose a service requirement such as:
    \begin{equation*}
        \text{average waiting time} \leq 5 \text{ minutes}
    \end{equation*}
    And try to minimize the number of open desks. Usually, the trade-off is between lower operating cost and better service quality.

    \highspace
    This example is slightly different from the earlier ones because quantities such as customer arrivals and waiting times may involve \textbf{uncertainty}. That will later be one reason why simulation can be useful.
\end{examplebox}

\highspace
\begin{flushleft}
    \textcolor{Green3}{\faIcon{code-branch} \textbf{Multicriteria decisions}}
\end{flushleft}
So far, most examples had one clear objective: minimize cost, minimize time, or maximize profit. But many \textbf{real problems have several objectives}.

\highspace
For instance, consider choosing a laptop. We might care about price, weight, performance. The difficulty is that these objectives can conflict.
\begin{itemize}
    \item Laptop $A$ may be cheaper, heavier and slower.
    \item Laptop $B$ may be more expensive, lighter and faster.
\end{itemize}
Then there may be no universally ``\emph{best}'' laptop. The decision depends on how much we value each criterion. This is called a \definitionWithSpecificIndex{multicriteria}{Multicriteria Problem} or \definitionWithSpecificIndex{multi-objective problem}{Multi-Objective Problem}.

\highspace
Conceptually, instead of one \textbf{objective function} $f(x)$, we may have \textbf{several}:
\begin{equation*}
    f_1(x), f_2(x), \dots, f_k(x)
\end{equation*}
For example:
\begin{equation*}
    \min f_1(x) = \text{price}, \quad \min f_2(x) = \text{weight}, \quad \max f_3(x) = \text{performance}
\end{equation*}
Later we will see ways of reducing this to a single optimization model.

\highspace
\begin{examplebox}[: Maximum clique as a decision problem]
    This is another graph problem, but unlike shortest path or spanning tree, it is \textbf{computationally much harder}.

    \highspace
    Suppose we have a social network represented by
    \begin{equation*}
        G=(N,E)
    \end{equation*}
    Each node is a person. An edge means two people are connected. A \definition{Clique} is a \textbf{subset of nodes in which every pair is connected}. For example, if:
    \begin{equation*}
        \left\{A, B, C, D\right\}
    \end{equation*}
    Is a clique, then every pair must have an edge:
    \begin{equation*}
        \{A,B\}, \{A,C\}, \{A,D\}, \{B,C\}, \{B,D\}, \{C,D\}
    \end{equation*}
    So a clique represents a group where everyone is directly connected to everyone else. The \definition{Maximum Clique Problem} is to \hl{find a clique containing the largest possible number of nodes.} The objective is therefore:
    \begin{equation*}
        \max \left|\text{clique}\right|
    \end{equation*}
    One application is identifying highly interconnected communities in social networks.

    \highspace
    \textcolor{Green3}{\faIcon{question-circle} \textbf{Why is this example especially interesting?}} Because the problem looks simple to state, but it is algorithmically difficult. And this is an important OR theme: \hl{some problems are easy to describe but hard to solve.} Shortest path and maximum clique are both graph problems, but their computational difficulty is radically different. Later, when complexity enters the course, maximum clique becomes a classic example of a hard combinatorial optimization problem.
\end{examplebox}

\highspace
\begin{takeawaysbox}
    \begin{itemize}
        \item A \textbf{decision-making problem} consists in choosing a feasible solution among many alternatives according to one or more criteria. Its fundamental ingredients are:
            \begin{equation*}
                \boxed{\text{Decisions} + \text{Feasibility conditions} + \text{Objective/criteria}}
            \end{equation*}

        \item Different real-world problems share the same OR structure:
            \begin{itemize}
                \item \textbf{Assignment}: assign jobs to machines minimizing total execution time;
                \item \textbf{Network design}: select links that connect all nodes at minimum total cost;
                \item \textbf{Shortest path}: find an $s$-$t$ path of minimum total arc weight.
            \end{itemize}

        \item The number of alternatives can grow extremely quickly: an assignment problem with $m$ jobs has $m!$ feasible assignments, while a network with $m$ possible edges has up to $2^m$ subsets of edges. Hence, \textbf{enumerating all alternatives is generally not a viable solution method}.

        \item A criterion does not have to represent only monetary cost: it may represent \textbf{time, distance, profit, service quality}, or several conflicting quantities in a \textbf{multicriteria problem}.

        \item A \textbf{problem} can be \textbf{easy to state but difficult to solve}. The shortest-path and maximum-clique problems are both graph problems, yet their computational difficulty is very different.
    \end{itemize}
\end{takeawaysbox}
